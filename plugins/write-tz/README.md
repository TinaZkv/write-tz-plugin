# Плагин `write-tz`

Навык написания технических заданий (ТЗ / продуктовых спецификаций) по единому
стандарту команды.

**Что делает:** превращает бизнес-контекст + макеты в готовое к разработке ТЗ в
разметке трекера. Держит фиксированную структуру разделов, директивный блок
«Что нужно сделать», исчерпывающее описание UI-состояний, дословные тексты,
права, модалки, уведомления, онбординг, аналитику, таблицу текстов под перевод.
Недостающее уточняет у автора и подсвечивает edge cases, а не достраивает молча.

**Что НЕ делает:** не выдумывает терминологию, формат и роли продукта — берёт их
из проектного `CLAUDE.md`. Без проектного контекста соберёт только каркас.

## Состав

- `skills/write-tz/SKILL.md` — навык (форма ТЗ, правила, чек-лист).
- `skills/write-tz/mockup-explanation-template.md` — шаблон письменного пояснения
  к макету (способ B; способ A — скриншот с комментариями прямо в чат).
- `skills/write-tz/examples/` — два эталона: форма A (новая фича) и форма B
  (сквозное изменение на многих экранах).

## Установка

См. корневой `README.md` репозитория: вариант 1 — через `/plugin` (CLI), вариант
2 — копированием папки `skills/write-tz` в `~/.claude/skills/` (для десктоп-
приложения / Cowork, где `/plugin` недоступен).

## Использование

Открыть Claude Code в папке фичи (с её `CLAUDE.md` и макетами), описать задачу,
подать макеты, сказать «напиши ТЗ». Навык задаст уточняющие вопросы (включая —
нужны ли разделы «Сценарии» и «Критерии приёмки») и выдаст файл
`ТЗ_[тикет]_[краткое].md` в разметке трекера.

## База знаний Brand Analytics (для команды BA)

Навык интегрирован с базой знаний продукта Brand Analytics. При запуске он
**сам разворачивает и обновляет** базу.

### Что нужно сделать коллеге (один раз)

1. Установить плагин `write-tz` (см. «Установка»).
2. Настроить SSH-ключ к `gitlab.pltrm.net` — **единственное обязательное
   предусловие**. База знаний — приватный репозиторий, без ключа clone/pull
   недоступны.

Как навык находит базу при запуске `/write-tz`:
- **путь известен из контекста** — проектный `CLAUDE.md` (раздел «База знаний»),
  глобальный `CLAUDE.md` или память / `IDENTITY.md` — берёт его и сообщает
  источник;
- **нигде не нашёл (или не уверен)** — **спросит сообщением**, где лежит папка
  `product-knowledge-base` (она может быть где угодно, хоть на внешнем диске), и
  предложит записать путь в `CLAUDE.md`, чтобы больше не спрашивать;
- базы ещё нет — склонирует (по умолчанию в `~/product-knowledge-base` или куда
  укажешь);
- база на месте — обновит (`git pull`) и прочитает термины, стоп-слова, роли и
  нужные `reference_*.md` по теме ТЗ.

Навык **не сканирует диск** и **не клонирует дубль молча** — если он не нашёл
путь сам и не уверен, он спрашивает.

### Чтобы навык не спрашивал каждый раз

Объяви путь к базе в проектном `CLAUDE.md` разделом «База знаний» — тогда навык
берёт его без вопросов. Готовый фрагмент — `skills/write-tz/CLAUDE.md.ba-example`.

### Опционально: BA-контекст в любой сессии

Чтобы термины и ограничения BA подгружались не только в скилле, а в любой
сессии, добавь в конец `~/.claude/CLAUDE.md` импорт по фактическому пути базы:

```
@~/product-knowledge-base/CLAUDE.md
```

Делать это лучше **после** первого запуска скилла (когда база уже склонирована),
иначе импорт укажет на ещё несуществующий файл до первого `/write-tz`.

### Где что лежит

| Что | Где |
|---|---|
| База знаний (термины, `reference_*.md`) | GitLab `zykova/product-knowledge-base` → локально по пути из `CLAUDE.md`; не объявлен — навык спросит (по умолчанию клонирует в `~/product-knowledge-base`) |
| Контекст для ТЗ (термины, роли, маршрутизация) | корневой `CLAUDE.md` базы знаний (см. `skills/write-tz/CLAUDE.md.ba-example`) |
| Сам навык | этот плагин, `skills/write-tz/SKILL.md` |
