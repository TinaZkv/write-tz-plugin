h1. Лимит кредитов на правило с промптом и автоостановка

h2. 1. Контекст и цель

Правило с промптом обрабатывает сообщения на потоке и расходует кредиты ИИ-тегирования. Без потолка одно правило способно выработать месячный баланс аккаунта незаметно для аналитика. Цель — дать на правило необязательный месячный лимит кредитов, останавливать правило при исчерпании и заранее предупреждать о подходе к порогу.

h2. 2. Что нужно сделать

# Добавить в форму правила с промптом необязательное поле «Лимит кредитов в месяц».
# Реализовать автоостановку правила при достижении лимита кредитов в текущем отчётном периоде (статус «Остановлено по лимиту»).
# Реализовать автовозобновление правила в новом отчётном периоде со сбросом счётчика расхода в 0.
# Добавить уведомления на 70% и 80% от лимита (по правилу и по аккаунту) и при исчерпании — каналы in-app и email.
# Вывести в списке правил колонку «Расход / лимит» и статус «Остановлено по лимиту».

h2. 3. Поведение при редактировании и удалении

* Изменение лимита в большую сторону у остановленного по лимиту правила — правило возобновляется немедленно, если новый лимит выше текущего расхода. *Важно. Критично.* Уже списанные за период кредиты не возвращаются.
* Снятие лимита (очистка поля) — правило работает без потолка; ранее списанное сохраняется.
* Удаление правила — счётчик расхода правила удаляется вместе с ним; уже выполненная разметка сообщений сохраняется.

h2. 4. Права доступа

* Поле «Лимит кредитов в месяц» видит и редактирует роль, имеющая право создавать правила с промптом: Супер-администратор, администратор аккаунта; модератор — только при праве «ИИ-тегирование».
* Роль без права «ИИ-тегирование» не видит блок «Промпт» и поле лимита в форме правила.

h2. 5. Сценарии

# Аналитик открывает форму правила с промптом → задаёт «Лимит кредитов в месяц» = 5000 → сохраняет → правило работает, пока израсходовано < 5000 кредитов в текущем периоде.
# Расход достигает 70% → приходит уведомление, правило продолжает работать.
# Расход достигает 100% → правило автоматически останавливается, приходит уведомление об исчерпании.
# Наступает новый отчётный период → счётчик расхода обнуляется, правило автоматически возобновляется.

h2. 6. Критерии приёмки

* Дано правило с лимитом 5000, когда суммарный расход за период достигает 3500 (70%), тогда отправляется уведомление «70%» по каналам in-app и email, статус правила не меняется.
* Дано правило с лимитом 5000, когда расход достигает 5000, тогда правило переходит в статус «Остановлено по лимиту» и новые сообщения им не обрабатываются.
* Дано остановленное по лимиту правило, когда начинается новый отчётный период, тогда счётчик расхода = 0 и правило снова обрабатывает поток без действий пользователя.
* Дефект: уведомление «80%» приходит после фактического исчерпания; правило продолжает списывать кредиты после статуса «Остановлено по лимиту».

h2. 7. Отображение в списках

В списке правил у правила с лимитом выводится колонка «Расход / лимит» в формате {{[израсходовано] / [лимит] кр.}}. Остановленное по лимиту правило помечается статусом «Остановлено по лимиту».

h2. 8. Аналитика и события

|| Событие || Когда пишется || Параметры ||
| rule_limit_set | сохранение правила с непустым лимитом | rule_id, limit_value |
| rule_limit_threshold | достижение 70% / 80% | rule_id, threshold, scope (rule/account) |
| rule_stopped_by_limit | автоостановка по исчерпанию | rule_id, period |
| rule_resumed_new_period | автовозобновление в новом периоде | rule_id, period |

Покрывает бизнес-метрику «расход кредитов под контролем» из §5 бизнес-контекста.
